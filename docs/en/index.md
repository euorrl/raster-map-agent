# Raster Map Agent Documentation

中文版: [首页](../index.md)

Raster Map Agent is a natural-language-driven, controlled Raster Workflow Agent. V1 can currently run a local end-to-end Sentinel-2 index product generation workflow and output consistently named result files.

V2 adds the service and presentation loop around the V1 workflow: a local Docker backend provides FastAPI / Redis / worker job services, a Vue frontend is deployed on Vercel, and the backend is accessed through a public intranet tunnel URL from the local machine.

## V1 Capability Overview

Current V1 supports:

- natural-language planner;
- route decision;
- two routes: `raster_product_generate` and `direct_answer`;
- six Sentinel-2 index products: NDVI, SAVI, NDWI, NDMI, NDBI, NBR;
- real STAC search, image download, AOI clipping, index calculation, and preview rendering;
- metadata export and final answer generation;
- `raster_prepare` validator / adjuster retry loop;
- local workspace creation and intermediate file cleanup.

## Current Workflow

```text
planner
-> route decision
-> registry if raster task
-> compiler
-> execute_tool loop
-> optional validate_tool / adjust_tool loop
-> final answer
```

Tool calls for the raster route are generated by the compiler, not freely chosen by the LLM:

```text
workspace.create_workspace
raster_prepare.prepare_raster_inputs
index_calculation.calculate_raster_index
render_preview.render_index_preview
metadata.export_metadata
answer.generate_final_answer
```

The direct answer route executes only:

```text
answer.generate_final_answer
```

## Output Structure

All index products use the same output names:

```text
data/<uuid>/output/
  metadata.json
  preview.png
  result.tif
```

Product type, index name, formula, data source, time range, and spatial information are written to `metadata.json` rather than encoded in file names.

## V2 Capability Overview

V2 completes the service layer, frontend, and local deployment demo loop without changing the V1 workflow, tool chain, index algorithms, or controlled execution architecture.

Current V2 supports:

- FastAPI backend that wraps each user request as a `job`;
- Redis queue for storing job status and managing the worker task queue;
- 2 workers by default, consuming tasks concurrently and calling the existing workflow;
- `POST /jobs` to create a task;
- `GET /jobs/{job_id}` to query task status, stage, and errors;
- `GET /jobs/{job_id}/metadata` to download `metadata.json`;
- `GET /jobs/{job_id}/preview` to download or display `preview.png`;
- `GET /jobs/{job_id}/result` to download `result.tif`;
- `GET /health` backend health check;
- worker heartbeat and fallback handling for stale running jobs;
- 30-minute job / workspace lifecycle cleanup;
- Vue / Vite / TypeScript frontend;
- frontend submission of natural-language requests, job polling, final answer display, and preview display;
- frontend downloads for `metadata.json`, `preview.png`, and `result.tif`;
- Vercel frontend deployment;
- public access to the local Docker backend through an intranet tunnel.

Current V2 deployment shape:

```text
Vercel frontend
-> intranet tunnel public URL
-> local Docker backend
-> FastAPI / Redis / workers
```

Quick access: https://raster-map-agent.vercel.app/
